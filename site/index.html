A tiny time series database

Compress the readings. Skip the rest.

shrunk packs time-stamped numbers into 1,024-point blocks, encodes each block with whichever codec produces the smallest output, and labels every block with its time range, value range, count, and sum. Queries read the labels and skip the blocks that cannot match.

The block

Every block carries its own summary.

A block is an immutable run of 1,024 readings. When it fills, shrunk writes a small header beside the compressed payload. Counts, sums, and value ranges come from the header, and range checks use it to skip blocks without touching the payload.

field meaning size
t_min, t_max First and last timestamp in the block 16 B
v_min, v_max Lowest and highest value, ignored when the NaN flag is set 16 B
count Readings in the block, used for counts and averages 4 B
sum Total of all finite values, used for averages 8 B
codec, flags Which encoder won, plus sum-present and has-NaN bits 2 B
payload_len Compressed size of the payload that follows 4 B
crc32 × 2 One checksum for the header, one for the payload 8 B

That is 58 bytes per block, header and checksums. For 1,024 readings it costs about 0.45 bits per point.

The query

Questions get answered at the lid.

No index server, no column scan. The query path walks block headers in order and decodes only the blocks that can still contain an answer.

avg(cpu.load) over all points

Divide the sums by the counts

Every block already stores its total and its point count. A covered block is answered from the header, so nothing is unpacked.

The codecs

Seven encoders. The smallest result wins.

Each block is encoded with every codec that can represent it, and the shortest output is kept. Flat sensors and counters compress far better than noisy floats, and the format adapts per block.

Run it

One binary, one file, no server.

shrunk is a Rust crate and CLI with no runtime dependencies. Build it, run the demo, and read the format. GPL-3.0.
